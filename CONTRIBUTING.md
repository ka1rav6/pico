# Contributing

First of all, thank you for considering contributing! 

Whether you're fixing a bug, improving documentation, suggesting an idea, or implementing a new feature, your contributions are greatly appreciated.

## Ways to Contribute

You can contribute by:

- Reporting bugs
- Suggesting new features or improvements
- Improving documentation
- Fixing bugs
- Writing tests
- Improving performance
- Refactoring existing code
- Reviewing pull requests

## Before You Start

Before starting work on a large feature:

1. Check existing issues and pull requests.
2. If no issue exists, create one to discuss your proposal.
3. Wait for feedback before investing significant time.

You will be assigned that feature afterwards.
This helps avoid duplicated work and ensures the feature aligns with the project's goals.

## Coding Guidelines

Please follow these guidelines:

- Keep code simple and readable.
- Follow the existing coding style.
- Write meaningful commit messages.
- Add tests for new functionality whenever possible.
- Update documentation if behavior changes.
- Avoid unnecessary dependencies.
- Follow the zig format style guide
- There is a strict NO AI CODE POLICY in act too as this project aims to be a zig community project

---

## Commit Messages

Use clear and descriptive commit messages.

Examples:

```
fix: prevent null pointer dereference
feat: add support for shared libraries
docs: improve installation guide
refactor: simplify parser logic
```

---

## Pull Request Guidelines

Before opening a pull request, ensure that:

- [ ] The project builds successfully.
- [ ] Tests pass.
- [ ] New functionality includes tests where appropriate.
- [ ] Documentation has been updated if needed.
- [ ] Your branch is up to date with the main branch.

When creating the PR:

- Clearly describe what changed.
- Explain why the change is needed.
- Link any related issues.

---

## Reporting Bugs

When reporting a bug, please include:

- Operating system
- Compiler/version
- Project version
- Steps to reproduce
- Expected behavior
- Actual behavior
- Error messages or logs

---

## Feature Requests

Feature requests should include:

- The problem you're trying to solve.
- Your proposed solution.
- Possible alternatives.
- Any drawbacks or tradeoffs.

---

## Code of Conduct

Please be respectful and constructive.
Treat everyone with kindness and professionalism. We want this project to be welcoming to contributors of all experience levels.

---

## Questions

If you're unsure about anything, feel free to open a discussion or issue before getting started.
Thanks again for contributing!
